## 1. 整理方法与版权边界

- 不大段复制原帖，所有题目均按技术考点重新表述。
- 合并不同帖子中的同义问题，保留代表性来源编号。
- 将“背定义”改成更接近真实面试的项目追问和故障场景。
- `A` 类来源是候选人自述的具体面试过程；`B` 类是面试官/从业者复盘；`C` 类是社区汇总题库。
- 频率是本次样本中的相对信号，不代表完整市场统计。

## 2. 社区面经反映出的考察重点

| 优先级 | 方向 | 典型追问 |
|---|---|---|
| 很高 | 项目真实性和个人贡献 | 输入输出、数据、指标、难点、失败、为什么这样选 |
| 很高 | RAG 全链路 | Chunk、Embedding、BM25、混合检索、召回率、幻觉 |
| 高 | Agent/Workflow 架构 | ReAct、工具调用、状态、Checkpoint、循环终止 |
| 高 | 工程与后端基础 | SLA、并发、重试、RPC、缓存、数据库、线上排障 |
| 中高 | MCP、Skill、A2A | 定位、区别、适用场景、安全风险 |
| 中高 | 模型与训练 | SFT、DPO/GRPO、Embedding Loss、数据构造 |
| 中 | 评测与业务价值 | 测试集、任务成功、ROI、延迟、成本 |
| 中 | 现场编码 | 配置热加载、算法题、工程代码和 AI Coding 使用 |

## 11. 高频追问链模板

面试官通常会沿以下路径连续追问：

```text
你做了什么？
-> 为什么这样做？
-> 还有哪些候选方案？
-> 数据和指标是什么？
-> 失败过什么？
-> 线上规模与成本是多少？
-> 如果扩大十倍怎么办？
-> 如何证明改进不是偶然？
```

准备项目时，应为每个关键决策准备“约束、候选方案、实验、指标、失败和最终取舍”。

## 12. 答题结构

### 系统设计题

`需求/约束 -> 架构分层 -> 数据与状态 -> 失败处理 -> 安全 -> 指标 -> 权衡`。

### 项目题

`背景 -> 个人责任 -> 技术难点 -> 方案选择 -> 实验指标 -> 线上结果 -> 复盘`。

### 故障题

`现象 -> 影响范围 -> Trace/指标 -> 根因假设 -> 验证 -> 修复 -> 防复发`。

### 对比题

先给出比较维度，再给结论；避免只罗列定义。
