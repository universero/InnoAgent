# 框架、协议与基础设施选型

> 导航：[总目录](../README.md) | [学习路线](02-分阶段学习路线.md) | [综合项目](03-综合项目.md)

## 1. 先选架构，再选框架

选型前先回答：

1. 这是确定性 Workflow、单 Agent Loop，还是多 Agent？
2. 是否需要长任务持久化、审批、恢复和取消？
3. 是否执行不可信代码或浏览器操作？
4. 是否需要多模型、自托管、私有数据和多租户？
5. 状态、工具和 Trace 能否脱离框架迁移？

## 2. 定位地图

| 类别 | 代表项目/标准 | 主要定位 | 重点验证 |
|---|---|---|---|
| 轻量 Agent SDK | OpenAI Agents SDK、smolagents | Loop、Tools、Handoff | 控制透明度、厂商绑定 |
| Stateful Graph | LangGraph | 状态图、持久化、HITL | 状态模型、部署和迁移 |
| Enterprise Agent | Microsoft Agent Framework | Agent + Workflow | 技术栈、云集成 |
| Multi-agent | AutoGen、CAMEL | 角色协作与研究 | 终止、状态、成本 |
| RAG/Data | LlamaIndex、Haystack、GraphRAG | 数据接入和检索 | 解析、ACL、评测 |
| Durable Workflow | Temporal | 长任务可靠执行 | 确定性、运维成本 |
| Tool Protocol | MCP、OpenAPI、JSON Schema | 工具互操作 | 授权、安全、版本 |
| Agent Protocol | A2A | 跨 Agent 任务协作 | 身份、信任、治理 |
| Model Gateway | LiteLLM | 多模型、路由、Fallback | 行为兼容、稳定性 |
| Inference | vLLM、Ray Serve | 自托管推理 | GPU、缓存、吞吐 |
| Observability | OTel、OpenInference、Langfuse、Phoenix | Trace 和评测 | 数据治理、开放标准 |
| Sandbox | Firecracker、gVisor、Docker、E2B | 隔离执行 | 网络、凭据、多租户 |

## 3. 场景建议

### 快速原型

轻量 SDK + 少量原生工具 + SQLite/PostgreSQL + 基础 Trace。优先看清控制流，不要过早平台化。

### 企业知识与行动助手

State Graph/Workflow + RAG + 权限过滤 + MCP/内部工具 + HITL + OTel。

### 长任务研究或运营 Agent

Durable Workflow + 队列 + Checkpoint + Artifact Store + 模型路由。

### 代码/浏览器 Agent

状态图 + 代码/浏览器沙箱 + 测试 Verifier + 高风险审批 + 完整动作 Trace。

### 多 Agent 平台

先证明单 Agent 基线，再引入角色协议、共享任务板、A2A 和 Credit Assignment。

## 4. PoC 评分表

| 维度 | 权重建议 |
|---|---:|
| 任务成功和可控性 | 25% |
| 状态、恢复和幂等 | 15% |
| 权限、安全和审计 | 15% |
| 可观测和评测 | 15% |
| 可迁移与开放标准 | 10% |
| 性能与成本 | 10% |
| 生态、维护和团队匹配 | 10% |

PoC 必须使用真实故障、权限和长尾任务，不只演示 Happy Path。

## 5. 避免锁定

- 业务状态使用自己的 Schema，不只存框架对象。
- 工具接口使用 JSON Schema/OpenAPI/MCP 等标准。
- Trace 导出 OTLP/OpenInference。
- Prompt、工作流和评测数据进入版本库。
- 模型调用通过适配层，保留模型特有能力配置。
- Artifact 使用可迁移对象存储和稳定 URI。

## 6. 最终选型问题

1. 框架是否隐藏模型调用、自动重试和系统 Prompt？
2. 能否从任意节点恢复并修改状态？
3. 是否支持幂等、有副作用工具和人工审批？
4. 能否导出全量 Trace 和评测数据？
5. 多租户、身份和数据地域如何实现？
6. 版本升级或项目停止维护时迁移成本多高？
7. 团队能否调试框架内部行为？
