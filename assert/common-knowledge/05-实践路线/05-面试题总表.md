## 回答方法

高质量回答通常包含：定义与边界、适用条件、失败模式、工程实现、评测指标和一个真实权衡。避免只背框架 API 或罗列论文名称。

1. 项目的真实用户、输入、输出和业务指标是什么？
2. 为什么使用 Agent，而不是固定 Workflow？

4. 数据从哪里来，规模和质量如何证明？
5. RAG 的 Chunk、召回率和幻觉分别如何评测？
6. SLA、并发、延迟和 Cost per Success 是多少？
7. Checkpoint 保存时机和写操作幂等如何设计？
8. 如果规模扩大十倍，当前架构先在哪里失效？
9. 如何从一次错误回答追踪到具体模型、Prompt 和工具？
10. 为什么选择当前方案，做过哪些对照实验？
